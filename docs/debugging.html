Debugging

Check paths, timing, and pointer events first.

Most issues in this project come from asset paths, ScrollTrigger timing, starting animation states, or layers blocking clicks.

Build Check

Run this before sharing the project:

npm run build

If the build passes, Vite can resolve the scripts, styles, and runtime asset paths.

Broken Images

All runtime media should live in public/assets/.

<img src="/assets/example.png" alt="Example">
background-image: url('/assets/example.png');
  • Check the file exists in public/assets/.
  • Check filename case exactly, especially .PNG vs .png.
  • Check the path starts with /assets/.

ScrollTrigger Feels Wrong

  • A new scene may have been added without adjusting timeline timing.
  • An element may start with the wrong opacity, autoAlpha, or transform.
  • Fonts or images may load late and change layout after ScrollTrigger measured the page.
ScrollTrigger.refresh()

Button Hover Does Not Show

The final CTA button is styled in src/styles/main.css under:

.cta-button
.cta-button::before
.cta-button:hover::before

The border draw effect works by changing four background-size values on the ::before pseudo-element.

Interaction Does Not Click

Most scene layers start with pointer-events: none so they do not block scroll.

Interactive elements need their own pointer-events: auto.

.cta-button {
  pointer-events: auto;
}

Performance Notes

Prefer animating transform, opacity, and carefully used clip-path.

Avoid animating layout-heavy properties such as top, left, width, or height during scroll-heavy sections.
