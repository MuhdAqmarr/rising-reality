Architecture

The page is a fixed camera controlled by scroll.

This project is a single-page scrollytelling experience. It uses HTML sections, CSS layers, and one JavaScript animation controller instead of a component framework.

Core Pattern

  1. .scroll-container creates a very tall page.
  2. .camera is fixed to the viewport.
  3. Every .scene sits inside the camera.
  4. GSAP changes opacity, transforms, clipping, and text states as scroll progress advances.

Animation Stack

GSAP handles the actual animation values and sequencing.

ScrollTrigger connects the master timeline to the scroll position.

Lenis smooths scrolling, but the wheel movement is intentionally slowed with wheelMultiplier so the story does not rush forward. The important bridge is:

lenis.on('scroll', ScrollTrigger.update)
gsap.ticker.add((time) => {
  lenis.raf(time * 1000)
})

SplitType breaks selected text into chars, words, or lines so GSAP can animate smaller pieces of text.

Scroll Feel

The master timeline uses scrub: true. This makes the animation follow the scroll position directly instead of catching up with delayed smoothing.

The total scroll distance comes from .scroll-container in CSS. Increasing its height gives every animation beat more scroll room.

Scene Visibility

CSS starts most scenes hidden. JavaScript then uses gsap.set() to prepare the starting state. During the master timeline, scenes fade in and out using autoAlpha, opacity, and visibility.

Use autoAlpha when an element should become invisible and non-interactive. Use opacity when the element can stay in place but be visually transparent.

Interaction Model

Most of the website is scroll-driven. Scene 5 has a special interaction: the scroll reaches a lock marker, waits for the Enter key, then plays a transition into the next panel.
